# Volok

Копирование файлов и папок между двумя аккаунтами Яндекс Диска **без
скачивания данных на вашу машину**.

Копирует не Volok, а сам Яндекс: исходный ресурс на секунду публикуется,
целевой аккаунт сохраняет его к себе по публичной ссылке, публикация тут же
снимается. Трафик идёт между серверами Яндекса, ваш канал не задействован.

```
исходный Диск                    целевой Диск
     |                                 |
     |  1. PUT /resources/publish      |
     |  2. GET /resources -> public_key|
     |  3. POST /public/resources/save-to-disk
     |  4. GET <href> -> status        |
     |  5. PUT /resources/unpublish    |
```

## Что умеет

- рекурсивное копирование дерева папок и файлов между двумя аккаунтами;
- предварительный подсчёт объёма и проверка свободного места на приёмнике;
- устойчивость к обрывам: ретраи с экспоненциальной задержкой, `Retry-After`,
  манифест запуска и продолжение прерванного копирования (`--resume`);
- полностью безопасный пробный прогон (`--dry-run`);
- аккуратное удаление исходных данных после копирования — только по явному
  подтверждению и только в Корзину.

## Требования

- bash 4.0 или новее (в macOS из коробки 3.2, поставьте `brew install bash`);
- `curl`;
- `jq`.

Если чего-то не хватает, Volok на старте скажет, что именно, и подскажет
команду установки для вашей системы.

## Установка

```sh
git clone https://github.com/<ваш-аккаунт>/volok.git
cd volok
chmod +x volok.sh
./volok.sh --help
```

Можно положить симлинк в `~/.local/bin` — модули подключаются относительно
реального расположения скрипта, симлинк работает:

```sh
ln -s "$PWD/volok.sh" ~/.local/bin/volok
```

## Токены доступа

Токен нужен для каждого из двух аккаунтов.

1. Зайдите на <https://oauth.yandex.ru/> под нужным аккаунтом и создайте
   приложение (кнопка «Создать приложение»).
2. Платформа — «Веб-сервисы», Redirect URI можно указать
   `https://oauth.yandex.ru/verification_code`.
3. Запросите права:
   - `cloud_api:disk.read` — чтение файлов и папок;
   - `cloud_api:disk.write` — запись, создание папок, публикация, удаление;
   - `cloud_api:disk.app_folder` — доступ к папке приложения.
4. Получите OAuth-токен по инструкции Яндекса и повторите всё для второго
   аккаунта.

Токен — это пароль от вашего Диска. Volok никогда не печатает его в вывод и в
журнал, не передаёт аргументом командной строки (в `ps` его не видно) и хранит
заголовок авторизации во временном файле с правами `600`.

Передать токены можно тремя способами, по убыванию приоритета:

```sh
# 1. переменные окружения
export YANDEX_TOKEN_SRC='токен исходного аккаунта'
export YANDEX_TOKEN_DST='токен целевого аккаунта'

# 2. файл ~/.config/volok/config (см. config.example)
install -m 600 config.example ~/.config/volok/config

# 3. ничего не задавать - Volok спросит их при запуске, без эха
```

## Быстрый старт

```sh
./volok.sh                       # весь диалог: токены, папки, подтверждение
./volok.sh --dry-run             # прогон без единого изменяющего запроса
./volok.sh --src-path /Фото --dst-path /Бэкап/Фото
./volok.sh --resume 20260914-170811-756
```

Сценарий диалога:

1. проверка `curl` и `jq`;
2. токен исходного Диска;
3. токен целевого Диска;
4. проверка доступа: логин владельца и свободное место по каждому аккаунту,
   отдельное предупреждение, если оба токена от одного аккаунта;
5. исходная папка (по умолчанию `/`), проверяется на существование;
6. целевая папка (по умолчанию `/`), при отсутствии предлагается создать;
7. подсчёт файлов, папок и объёма, сверка со свободным местом;
8. сводка «откуда → куда, N файлов, X ГБ» и подтверждение (по умолчанию «нет»).

## Флаги

| Флаг | Значение |
| --- | --- |
| `--src-path ПУТЬ` | исходная папка, иначе спрашивается (по умолчанию `/`) |
| `--dst-path ПУТЬ` | целевая папка, иначе спрашивается (по умолчанию `/`) |
| `--on-conflict РЕЖИМ` | `skip` (по умолчанию), `overwrite`, `rename` |
| `--allow-fallback` | разрешить резервный путь download/upload |
| `--dry-run` | пройти весь сценарий без изменяющих запросов |
| `--resume ИД` | продолжить прерванный запуск |
| `--log-level УРОВЕНЬ` | `debug`, `info`, `warn`, `error` |
| `--verbose` | дублировать журнал в stderr |
| `--yes` | не спрашивать подтверждение перед копированием |
| `--no-color` | вывод без цветов |
| `--config ФАЙЛ` | другой файл конфигурации |
| `-h`, `--help` | справка |
| `-v`, `--version` | версия |

`--yes` не отключает подтверждение удаления: там всегда нужно ввести слово
целиком.

### Конфликты имён

- `skip` — файл, который уже есть в приёмнике, пропускается и отмечается в
  манифесте как `skipped`;
- `overwrite` — существующий файл удаляется (в Корзину) и копируется заново;
- `rename` — новая копия сохраняется как `имя (2).ext`.

### Резервный режим

Если серверное копирование отказало (например, ресурс слишком велик),
с флагом `--allow-fallback` Volok скачает файл через `/resources/download`
и зальёт через `/resources/upload`. По умолчанию это выключено, потому что
расходует ваш трафик: данные пойдут через вашу машину.

## Устойчивость к сбоям

- до 5 попыток на запрос, задержки 1-2-4-8-16 секунд плюс случайный джиттер;
- повторяются 429, 500, 502, 503, 504 и сетевые обрывы;
- 401, 403 и 404 не повторяются;
- на 429 учитывается заголовок `Retry-After`;
- 507 (на приёмнике кончилось место) останавливает всю операцию, а не один
  файл: дальше копировать бессмысленно.

Каждый запуск пишет своё состояние в
`~/.local/state/volok/<идентификатор-запуска>/`:

| Файл | Что внутри |
| --- | --- |
| `manifest.tsv` | `статус <TAB> путь <TAB> размер <TAB> время`, статусы `copied`, `skipped`, `failed` |
| `errors.log` | `ISO8601 <TAB> путь <TAB> HTTP-код <TAB> сообщение API` |
| `scan.dirs`, `scan.files` | результат обхода исходного дерева |
| `run.conf` | параметры запуска для `--resume` |
| `published.list` | ресурсы, опубликованные прямо сейчас |
| `volok.log` | журнал с маскированными токенами |

Идентификатор запуска печатается в сводке; `--resume ИД` продолжает работу,
пропуская всё, что уже отмечено как `copied`. Пробный запуск (`--dry-run`)
манифест не пишет, чтобы не мешать настоящему `--resume`.

Табуляции, переводы строк и обратные слэши в именах файлов экранируются при
записи в эти файлы, так что кириллица, пробелы и любые спецсимволы переживают
запись и чтение без потерь.

## Удаление исходных данных

После копирования Volok предлагает меню:

```
  [1] Нет, ничего не удалять
  [2] Да, удалить только успешно скопированные файлы
  [3] Да, удалить всё содержимое исходной папки
```

Правила жёсткие:

- по умолчанию выбран пункт 1;
- пункт 2 удаляет ровно то, что помечено в манифесте как `copied`, дерево
  заново не обходится;
- пункт 3 недоступен, если есть хотя бы одна ошибка, — иначе можно стереть то,
  что не доехало до приёмника;
- перед удалением нужно ввести слово `УДАЛИТЬ` целиком, `y` не принимается;
- удаление идёт в Корзину (`permanently=false`), это последний рубеж отката;
- при `--dry-run` удаление не выполняется никогда.

## Коды возврата

| Код | Значение |
| --- | --- |
| 0 | успех |
| 1 | ошибка окружения: нет зависимостей, нет папки, не хватает места |
| 2 | ошибка авторизации |
| 3 | копирование завершено, но с ошибками |
| 4 | прервано пользователем |

## Безопасность

**Честное предупреждение: на время копирования каждый файл доступен по
публичной ссылке.** Иначе серверное копирование между разными аккаунтами
не работает — целевой аккаунт забирает файл именно по этой ссылке.

Что это значит на практике:

- ссылка живёт секунды: публикация снимается сразу после того, как операция
  сохранения завершилась;
- ссылка не публикуется нигде и содержит непредсказуемый `public_key`, но это
  всё-таки ссылка без пароля: кто её знает, тот скачает файл;
- публикация снимается всегда, в том числе при падении и при `Ctrl+C`:
  список опубликованных путей ведётся в `published.list`, а обработчик
  выхода (`trap EXIT`) проходит по нему и снимает публикации;
- если снять публикацию всё-таки не удалось, Volok напечатает путь и попросит
  снять её вручную — не игнорируйте это сообщение;
- если данные секретны настолько, что даже секундная ссылка неприемлема,
  используйте `--allow-fallback` и откажитесь от серверного копирования, либо
  не используйте Volok.

Про токены:

- токен не попадает ни в журнал, ни в вывод, ни в `ps`: заголовок авторизации
  передаётся curl через файл конфигурации с правами `600` во временном
  каталоге, который удаляется при выходе;
- журнал дополнительно маскирует всё, что похоже на токен;
- если `~/.config/volok/config` доступен не только вам, Volok предупредит;
  поставьте `chmod 600`.

### Как добавить новое хранилище

Ядро ничего не знает про Яндекс. Аккаунт адресуется «слотом» (`src`, `dst`),
слот привязан к провайдеру, вызовы идут через косвенное обращение по имени
функции — без `eval`:

```sh
provider_call dst mkdir '/Бэкап/2026'
```

Чтобы добавить Google Drive, OneDrive, Dropbox или S3, достаточно положить
рядом файл `src/providers/<имя>.sh` и дописать имя в `PROVIDER_KNOWN`.
Обязательные функции (первым аргументом всегда идёт слот):

| Функция | Что делает |
| --- | --- |
| `<p>_auth_check` | проверяет токен, печатает логин владельца |
| `<p>_quota` | печатает `total <TAB> used <TAB> available` в байтах |
| `<p>_list_dir` | листинг одной папки со всеми страницами: `тип <TAB> путь <TAB> размер` |
| `<p>_mkdir` | создаёт папку, идемпотентно |
| `<p>_server_copy` | серверное копирование между аккаунтами |
| `<p>_download` | поток вниз, в stdout |
| `<p>_upload` | поток вверх, из stdin |
| `<p>_delete` | удаление, по умолчанию в корзину |

Необязательные: `<p>_exists`, `<p>_normpath`, `<p>_cleanup` (снятие
временной публикации при аварийном выходе).

Об ошибке провайдер сообщает двумя переменными: `PROVIDER_STATUS` (код HTTP
или 0 для сетевого сбоя) и `PROVIDER_MESSAGE` (текст от сервиса). Именно по
ним ядро принимает решения: 409 — конфликт имён, 507 — остановка, 401 и 403 —
не повторять.

## Разработка

```sh
shellcheck -x volok.sh          # -x, чтобы проверить и подключаемые модули
bash -n volok.sh
```

`shellcheck -x volok.sh` проходит без единого замечания, и в коде нет ни одной
директивы `# shellcheck disable`. Отдельный модуль имеет смысл проверять
только вместе с точкой входа: сам по себе он выглядит как файл, который
присваивает переменные «в никуда», — их читают соседние модули.

Тестовых зависимостей нет: `--dry-run` проходит весь сценарий, не отправляя
ни одного изменяющего запроса, и это самый быстрый способ проверить правки.

Код держится в рамках: `set -euo pipefail`, `IFS` из перевода строки и
табуляции, никаких `eval`, все пути обрабатываются с учётом пробелов,
кириллицы и переводов строк, URL-кодирование вынесено в отдельную функцию.
